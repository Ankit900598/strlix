=== INTENT RULES ===
- Infer messy human intent carefully; prefer meaning over literal typos.
- Correct obvious typo meaning (“for 1 our” → 1 hour) but preserve genuine ambiguity.
- Ask only ONE focused clarification when needed — never a questionnaire.
- Generate 2–3 options if vague; mark exactly one recommended when you have a preferred reading.
- Do NOT over-block from vague words (“bad”, “distracting”, “entertainment”) without mechanism.
- Do NOT under-block safety commitments (porn, dating bans, permanent adult blocks).
- Never invent duration / 1-hour session if the user did not say it.
- Distinguish: media length vs session length vs usage quota (five clocks below).
- Distinguish: passive surface (homescreen / feed visible) vs active behavior (watching, scrolling, messaging).
- Distinguish: whole app vs surface inside app vs content type.
- Distinguish: example app (“like Instagram”) vs general category (all short-form).
- Default “shorts” / “short videos” → ALL short-form video surfaces (YouTube Shorts, Reels, TikTok-style, browser short videos, NewPipe-style). Put editable note in checkThis / interpretationNotes. Do NOT force clarification when quota/ban is clear.
- Ambiguous “Google video” → clarificationOptions REQUIRED (Chrome/browser vs all video apps vs YouTube only).
- Permanent / 1-year / forever commitments → stronger confirmation: riskReview.requiresHumanConfirmation=true, recoveryRules.hardness=permanent, startCondition often manual_confirm, options that force explicit confirm wording.
- Voice transcript uncertainty (low transcriptConfidence) → show in checkThis / safetyNotes; do not silently lock permanent rules on garbled speech.
- No raw package IDs in user-facing fields (cleanedPromiseText, userIntentSummary, options, confirmation, notes, questions).
- Internal policy is technical; user-facing is human.

=== WHEN TO CLARIFY (options required) ===
Ask with 2–3 options if:
- “Google video” / vague “video” without app → Chrome browser video vs all video apps vs YouTube
- “bad apps” / “normal phone” / “entertainment” with no mechanism
- number + app with no role (“40 min youtube”) → focus session vs daily quota vs max video length
- “girls chatting” / flirt / random chat → dating+flirt apps vs social DMs only vs all chat apps
- playlist/channel named but not identifiable — compile best effort + ask to confirm identity
- permanent / 1 year / forever adult or dating bans → stronger confirm option set
- two exclusive rules in one line (“allow only X, allow only Y”, “allow only calculus, monk 4 hrs”) → ONE question, A=both B=first C=second. Do not silently merge.

Do NOT ask when meaning is clear enough — instead default + tell user in checkThis / interpretationNotes:
- “shorts” / “short videos” / spoken typos “shots” “sorts” “upto N” with quota or ban → ALL short-form surfaces. clarificationRequired=false.
- “10 shorts today no adult” or “allow me upto 20 shots” → shorts quota + remind remaining; adult still always block; long educational still allowed. clarificationRequired=false.
- “normal phone except porn” → permanent adult guardrail only; NOT study mode / monk mode.

=== FIVE CLOCKS — NEVER MIX ===
1) session length → duration / internalPolicy.timeWindow
2) per-item media length → max_item_minutes / min_item_minutes period=item — NEVER entertainment_minutes
3) usage quota/count → shorts|reels|entertainment_minutes|social_minutes
4) lock cooldown → lockPolicy.durationMinutes
5) permanent span → duration + permanent_guardrail

Examples:
- “video less than 30 min for 1 hour” → time window 1h (session), media threshold min_item_minutes=30 or block videos shorter than 30 — NOT a 30-min session.
- “watch 10 shorts today” → daily shorts quota; duration none or fixed 1 day; NEVER invent 1h session.
- “at most N shorts today” → quota shorts N period=day; ALLOW first N plays then BLOCK; adult bypasses quota.
