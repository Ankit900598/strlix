## Mistake restated
Competitors gate the product behind a downloaded client (Windows/macOS/APK), treating the browser as a degraded, ad-laden teaser. The download is a funnel for upsell, DRM/anti-abuse hooks, and forced updates — but it costs the first session, the only one that matters. Appetize/now.gg win because a link is the product.

## Strlix solution (concrete UX + IA)
**Web is the product; client is an optional accelerator.**

1. **Zero-auth trial boot.** `strlix.app/p/<app-slug>` boots a real cloud Android in ≤8s with no signup. Anonymous session token in `localStorage`; account creation only when the user wants persistence ("Keep this phone" button in the top bar). Trial: 10 min, visible countdown pill, no ads, no watermark beyond a small Strlix chip.
2. **Phone-first canvas.** The page is a phone bezel centered on a plain background. No marketing chrome around it after boot. Everything else (app drawer, file drop, AI) is *inside* the phone frame:
   - **AI lives as an on-device assistant sheet** swiped up from the phone's nav bar — it sees the screen, can tap/type for you ("install this APK and sign in"), and renders as an Android surface, not a sidebar chatbot.
   - App install = the phone's own Strlix Store app, not a web page.
3. **Client parity ledger.** A `/why-app` page lists exactly what the native client adds (USB passthrough, >60fps, local file mount, background sessions) with a per-feature "works in browser?" column. No feature is silently web-disabled.
4. **No interstitial.** Download prompts appear only contextually: user plugs in a gamepad → inline toast "Gamepad works here; native client adds rumble."
5. **Share = link.** Session share produces a URL with view/control scopes. Recipients never download anything.

## Android 7+ / graceful degradation notes
- Probe order: WebRTC H.264 → WebRTC VP8 → WS JPEG-frame fallback (works on Chrome 60 / Android 7 WebView).
- Android 7 lacks `AVIF`/`WebCodecs`: gate on `typeof VideoDecoder`, fall back to `<video>` MSE, then canvas blits.
- No `ResizeObserver`/`:has()` — ship a 3KB polyfill and a flex-only bezel layout.
- Degrade resolution before framerate: 720p→540p→360p, cap 24fps on fallback path; show a quiet "Low-power stream" chip, never a modal.
- Touch events over Pointer Events when `PointerEvent` is undefined.

## Payment notes
Trial→paid upgrade happens **inside the phone** via the Strlix Store app. Stripe test-mode (`pk_test_…`) + Razorpay test keys behind `PAYMENTS_MODE=test`; server refuses live keys unless `PAYMENTS_MODE=live`. Test cards only, banner "Test mode — no charge". No download required to pay.

## Acceptance criteria
- Cold link → interactive Android screen in ≤8s on a mid-tier Android 7 phone, zero signup, zero download.
- No download CTA renders before first successful frame; none is modal, ever.
- Disabling WebRTC in the browser still yields a controllable (lower-fps) session via WS fallback.
- AI assistant is reachable only from inside the phone frame; no external chat panel exists in the DOM.
- Checkout completes with a Stripe test card and provisions a persistent phone without installing a client.
