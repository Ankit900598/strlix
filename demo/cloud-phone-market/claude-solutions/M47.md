## Mistake restated
M47: the player exposes no stream controls. One fixed encode ladder (e.g. 1080p/8 Mbps h264) is pushed to everyone, so a user on congested 4G gets stalls, 2s latency spikes, and black frames — and concludes "cloud phones don't work." Ops keeps one ladder because multi-profile encoders complicate scaling.

## Strlix solution (concrete UX + IA)
Controls live **inside the phone**, not in a settings page you leave the session for.

1. **Signal chip in the phone's status bar** (top-right of the rendered device frame, drawn by us, not Android): shows `HD · 42ms` / `SD · 180ms` / `LOW`. Tap → sheet slides up *over* the device screen, session keeps streaming.
2. **Stream sheet** — three presets + Auto:
   - `Auto (recommended)` — ABR, target latency 80ms
   - `Smooth` — 720p30, 1.5 Mbps, ~prioritize frame pacing
   - `Sharp` — 1080p60, 6 Mbps (disabled + reason text if measured bw < 4 Mbps: "Your link measured 2.1 Mbps")
   - `Data Saver` — 540p30, 600 kbps, h264 baseline
   Advanced disclosure: codec (Auto/H.264/VP8), fps cap, bitrate slider, "jitter buffer: low-latency | stable".
3. **AI inside the phone**: the Strlix assistant is an on-device overlay app. When it detects 3 stalls/30s it surfaces a heads-up notification *in the Android notification shade*: "Network dropped to 1.8 Mbps — switch to Smooth?" with **Switch** / **Keep**. One tap, no reload — server swaps encoder profile on the same WebRTC track via renegotiation-free `setParameters`.
4. **IA**: `Market → App detail → Launch → /phone/:sessionId`. Stream prefs persist per-device-profile in `localStorage` + server-side profile so the next launch starts correctly. No stream settings in global account settings (avoids two sources of truth); global page only shows "Default quality" which deep-links to the same sheet component.
5. **Honest telemetry**: sheet footer shows live `bitrate / fps / packet loss / decode time` so "blame cloud" becomes a diagnosable number. Copy-diagnostics button emits a JSON blob for support.

## Android 7+ / graceful degradation notes
- Android 7 WebView often lacks VP9/AV1 → `profiles.ts` gates codecs via `RTCRtpSender.getCapabilities('video')`; unsupported presets render greyed with "Not supported on this browser."
- If `getStats()` is missing/partial, hide the telemetry footer but keep manual presets working — never block the control on diagnostics.
- If WebRTC unavailable entirely, fall back to MJPEG/WS path at Data Saver settings only, chip reads `LOW · compat`.
- `navigator.connection.effectiveType === '2g'|'slow-2g'` → preselect Data Saver on first launch.
- Sheet is touch-first: 48dp targets, bitrate slider has ±step buttons for weak touch digitizers.

## Acceptance criteria
- Changing a preset mid-session updates video within 2s **without** tearing down the session or losing app state.
- On a link throttled to 1.5 Mbps, Auto settles to a stall-free profile within 10s; stalls/min < 1.
- Every preset the UI offers is actually decodable in the current browser (unsupported ones are disabled with a reason string).
- Preference persists across app relaunch on the same account+device class.
- Telemetry footer values match `getStats()` within one poll interval; diagnostics copy produces valid JSON.
