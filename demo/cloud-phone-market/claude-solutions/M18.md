## Mistake restated
DuoPlus-class vendors advertise a low hourly/monthly phone price, then add separately-named one-time charges (activation / "startup" / instance-creation / restart-after-idle fees) that are only explained in scattered beginner docs. Users see a headline price, get billed something else, and conclude the pricing is a bait. The fee exists to cover cold-start VM cost, so it can't just be deleted — it has to be made *visible, predictable, and avoidable*.

## Strlix solution (concrete UX + IA)
One rule, enforced in UI: **there is exactly one fee line for "bringing a phone online", and it is named the same string everywhere: `Cold start`.** No "activation", no "setup", no "instance fee".

1. **Two-state price chip on every phone card.** `₹X/hr running · ₹0 paused` plus `Cold start ₹Y (first boot + after 30 min paused)`. The chip is a single component; there is no card layout without it.
2. **Pre-boot confirm sheet (inside the phone shell, not a separate billing page).** Tapping Power shows: "Boot Pixel-7 · Cold start ₹Y now, then ₹X/hr. Stop anytime; pausing keeps state free for 30 min." Buttons: Boot / Keep paused. First boot of a session ever = sheet is non-skippable; afterwards a "don't ask" toggle turns it into a 4-second undo toast.
3. **Warm-pool badge = ₹0 cold start.** Devices already warm show `Instant · no cold start` in green. This turns the fee into a *choice* (pick a warm device or wait 20 s for a warm slot) rather than a surprise.
4. **Idle-reclaim countdown on the phone chrome.** A thin bar: "Paused 27:41 — free. At 30:00 storage releases and next boot costs a cold start." One-tap "Hold this device (₹Z/day)" to opt out.
5. **AI inside the phone**: the assistant is a launcher app on the device home screen. Ask "why was I charged ₹Y?" → it opens Wallet → the exact ledger row, highlighted, with the boot event timestamp and the device that caused it. No external chat widget.
6. **Ledger IA**: Wallet → *Events* (one row per chargeable event: Cold start, Runtime block, Hold) and *Estimate* (next 24 h projection from current state). Every row deep-links back to the device screen.
7. **Spend guard**: monthly cap; at 80% a system notification inside the phone, at 100% devices auto-pause instead of silently accruing.

## Android 7+ / graceful degradation notes
- Chip/sheet/bar are plain DOM + CSS (no `:has()`, no container queries; flex fallbacks), Chrome 60 tested.
- If WebSocket to :8789 drops, IdleBar switches to polled `/session` every 10 s and shows "estimate may lag" instead of a wrong countdown; boot stays blocked until a fresh quote returns — never charge on stale state.
- Assistant degrades to a static FAQ list if speech/streaming unavailable.
- Countdown uses server `serverNow` delta, not device clock.

## Payment notes
Test mode only: Stripe `pi_test_*` / Razorpay stub behind `PAYMENTS_MODE=test`; UI shows a persistent "Test mode — no real charges" ribbon. Cold start is authorized at boot confirm and captured only after `boot_ready`; failed boot = auto-void with a ledger row "Cold start reversed". Idempotency key = `${deviceId}:${bootEventId}` so retries never double-charge.

## Acceptance criteria
- Every surface that names a boot fee renders the string from `feeLabels.coldStart`; a test fails if any other fee noun ships.
- No charge event can occur without a preceding confirmed `BootSheet` or explicit "don't ask" consent recorded with timestamp.
- Warm devices boot with a ₹0 cold-start ledger row (row still written, value 0) — visible proof the fee was avoided.
- A user can go from any wallet charge to the causing device screen in ≤2 taps.
- Failed/aborted boot produces a reversal row within 60 s and no net balance change.
