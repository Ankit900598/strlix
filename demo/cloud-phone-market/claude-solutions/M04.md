## Mistake restated
Product/model pages show game and app tiles that read as "what's on this device." They are actually store recommendations. The user buys/rents the SKU, boots the phone, finds a bare launcher, and burns session one on downloads. The pattern survives because app logos drive SEO and click-through, and producing per-SKU truthful screenshots costs ops time.

## Strlix solution (concrete UX + IA)
Split the model page into two structurally different, non-adjacent zones with different visual grammar:

1. **"On this phone now"** — generated, not authored. A snapshot job runs the SKU's base image, dumps `pm list packages -3`, pulls launcher icons, and renders a live device frame. Tiles are square icons on the actual wallpaper, each with a `✓ preinstalled` chip. Header carries a timestamp: "Image build 2026-09-14 · verified by boot probe." No hand-written HTML can enter this zone; it reads only `image-manifest.json`.
2. **"Install in one tap after you start"** — different shape (16:9 cards, grayscale icons until hover), header "Not included. Est. download 1.4 GB / ~3 min on our pipe." Each card has an **Add to first-boot queue** toggle. Toggled apps are written into the session provision payload, so the installs run during the ~40s VM warm-up, not on the user's clock. Boot screen shows "Installing 3 queued apps… BGMI 62%."
3. **AI lives inside the phone.** A floating Strlix bubble over the stream, not a sidebar chat. Ask "is Genshin already here?" → it answers from the same manifest and offers a button that either launches the app or queues the install. No link-outs to a web chat.
4. **Compare drawer**: pick two SKUs, diff is computed from manifests — "+Google Play Games, −root shell, RAM 6→8 GB." Kills SEO-driven copy drift because copy is derived.
5. **Guardrail**: CI test fails the build if any string in the recommendations zone also appears in `preinstalled[]`, or if a manifest is older than 30 days.

## Android 7+ / graceful degradation notes
- Stream: WebRTC → MSE → 8 fps JPEG-over-WS fallback for Chrome 60-era WebViews.
- `PreinstalledGrid` is server-rendered static HTML; icons `loading="lazy"`, WebP with PNG `<picture>` fallback. Truth survives zero JS.
- `AiBubble` and queue toggles are progressive enhancement; without JS the recommendation cards show "installable after start" text and no toggle.
- Device frame PNG capped at 480px wide for ≤360dp screens; grid collapses 5→3 columns.

## Payment notes
Checkout stays test-mode: Stripe `pi_` test intents / Razorpay test keys behind `PAYMENTS_MODE=test`, with a persistent "No real charge" banner. Queued apps must never alter price — if a queued app is paid or region-locked, show "requires your own account" on the card and exclude it from the total.

## Acceptance criteria
- Every tile in "On this phone now" traces to an entry in that SKU's manifest; CI fails otherwise.
- Zero-overlap test passes: no app appears in both zones on any SKU page.
- Queued installs complete during warm-up for ≥80% of ≤500 MB apps; boot screen reports per-app progress.
- Manifest older than 30 days renders a "verification pending" state instead of stale icons.
- With JS disabled and on Android 7 Chrome 60, the preinstalled list and its build date render correctly.
