## Mistake restated
Competitors ship a shared VM image pool whose stream geometry (often ~1:1 or a desktop-ish ratio) doesn't match any real phone. The user's first frame says "this is a VM in a box," and the only fix is a free "change device" swap — an action the user must discover, and which is rationed. The root cause is economic: one image pool serves all SKUs, so per-SKU display profiles (resolution, DPI, bezel, cutout, refresh) never get authored.

## Strlix solution (concrete UX + IA)
**1. Aspect is a client-side contract, never a server surprise.** Every SKU in the catalog carries a `displayProfile`: `{w,h,dpi,refresh,cutout,cornerRadius,safeInsets}`. The market card renders the *actual* phone frame at that ratio before any session exists. What you see in the grid is pixel-identical to what boots.

**2. Letterbox-never policy.** On session start the client sends `?w=1080&h=2400&dpi=440` to the stream endpoint. If the server negotiates a different geometry, the player does **not** letterbox into a square canvas — it crops-to-phone inside the bezel and raises a non-blocking `AspectDriftBanner`: "Display renegotiating… (1024×1024 → 1080×2400)" with a live retry. Resize is issued via the existing desktop-api resize/IME channel, not a device swap.

**3. Instant reshape, no swap quota.** A `ReshapeSheet` (long-press the bezel, or Phone menu → Display) offers the SKU's native profile plus 3 presets (Compact 1080×2340, Tall 1080×2400, Tablet 1600×2560). Applying issues `POST /session/:id/display` → `wm size`/`wm density` inside the guest + stream reconfigure. Target <2s, session preserved. Reshapes are unlimited and free; they are a display op, not a device op.

**4. AI lives inside the phone.** The assistant is a guest-side floating bubble anchored to `safeInsets`, so it never overlaps the cutout and never becomes an external chat panel. It can act on aspect: "make this look like a Pixel 8" → calls the same display API.

**5. IA:** `/` catalog (framed cards) → `/device/:sku` (spec sheet with Display block: resolution, DPI, refresh, cutout type) → `/session/:id` (bezel + stream + AI bubble + Display sheet).

## Android 7+ / graceful degradation notes
- Guest API 24: `wm size`/`wm density` exist; cutout APIs do not. Cutout is drawn **client-side only** as bezel art; guest `safeInsets` are supplied as plain dp values the AI bubble respects manually.
- No WebRTC/H.264 in old WebViews → fall back to MJPEG at the same aspect; ratio correctness must not depend on codec.
- `aspect-ratio` CSS missing on Android 7 Chrome → padding-top percentage fallback in `frame.css`.
- Reshape unsupported (locked image) → sheet shows native profile only, disabled presets with reason text; never silently square.

## Acceptance criteria
- Catalog card ratio === first streamed frame ratio for all SKUs, verified by a snapshot test.
- No code path renders a 1:1 or letterboxed-into-square stream; drift triggers the banner + auto-reconfigure.
- Reshape completes in <2s with the session and running app preserved, unlimited times.
- On Android 7 + MJPEG fallback, the frame ratio is still exact.
- AI bubble never overlaps cutout or nav bar at any profile.
