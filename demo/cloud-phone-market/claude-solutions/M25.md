## Mistake restated
Device-farm competitors gate all pricing behind "Contact sales." A hobbyist who wants one cloud Android for an hour cannot see cost, cannot swipe a card, and bounces. The motion persists because enterprise ACV rewards price discrimination — but it forfeits the entire indie/long-tail funnel and any organic word-of-mouth.

## Strlix solution (concrete UX + IA)
**Price is a first-class object inside the phone, never a sales gate.**

1. **`/pricing` is static, crawlable, no auth.** Three tiers rendered as *phone frames*, not table rows: Free (1 device, 30 min/day, 720p, watermark), Solo ₹499/$6 per mo (3 devices, 1080p, ADB, persistent storage), Studio ₹2499/$30 (10 devices, team seats, API keys). Enterprise is a *fourth card with a visible starting floor* ("from $X/seat/mo, annual") + "Talk to us" — sales becomes an upsell, not a toll booth.
2. **Meter HUD inside the phone.** A collapsible pill at the top of the stream shows `₹0.00 · 12m left · Free`. Tap → sheet with live per-minute rate, session cost, and "Keep going" upgrade. Cost is never a surprise discovered at checkout.
3. **Pay-as-you-go without subscription.** "Add ₹100 credit" button; credits burn per device-minute. This is the indie escape hatch competitors lack.
4. **Upgrade happens *in* the phone.** At 2 min remaining, an in-stream Android-styled bottom sheet (rendered as a web overlay on the canvas, not a redirect) offers Continue → Stripe/Razorpay embedded element. Session state is preserved; the device is not destroyed, only frozen for 10 min.
5. **AI agent is price-aware.** Ask the in-phone assistant "how much to run this 3 hours?" → it answers from the same `pricing.json` the page renders. No hallucinated quotes.
6. **IA:** `/` → `/pricing` → `/try` (anonymous device, no signup, no card) → in-phone paywall → account created *after* first payment intent, not before.

## Android 7+ / graceful degradation notes
- Pricing page is plain HTML/CSS grid — readable with JS fully disabled; tier cards are `<section>`s that stack at <360px.
- `Intl.NumberFormat` currency wrapped in try/catch → fallback to `"₹" + toFixed(2)`.
- No `dialog` element, no `:has()`, no container queries; UpgradeSheet is a positioned div with a manual backdrop.
- MeterHUD degrades to a server-rendered static "Free · 30 min" badge if `fetch` fails twice; never blocks the canvas.
- Payment iframe on Chrome 51–59: if the embedded element fails to mount, fall back to a full-page redirect link.

## Payment notes
Test mode only. Stripe test keys (`pk_test_…`) + Razorpay test keys, selected by detected currency. `POST /billing/intent` returns a fake client secret and logs to `desktop-api/.data/billing-stub.jsonl`. A persistent red "TEST MODE — no card is charged" banner sits above any payment form. Real keys are read from env and absent by default, so a misconfigured deploy cannot charge.

## Acceptance criteria
- A logged-out visitor sees every self-serve price, including a numeric enterprise floor, within one click of `/` and with JS disabled.
- A visitor can reach a live streaming Android device from `/try` with zero signup and zero card, and sees a running cost/time meter within 5s.
- Hitting the free limit freezes the device for 10 min instead of destroying it; paying in the in-stream sheet resumes the *same* session.
- The in-phone AI quotes prices that exactly match `pricing.json` (asserted by a test that mutates the JSON and re-asks).
- No code path can reach a live payment processor without an explicitly set env key; default build shows the TEST MODE banner.
