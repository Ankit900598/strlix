## Mistake restated

Competitors ship a solo-user cloud phone, then graft sharing on later: the only share primitive is a link or "add member," which grants full device control (including clipboard, files, SMS/OTP, saved logins) with no scoping, no expiry, and no per-action log. An agency adds a freelancer to one client's device and they inherit the whole workspace; when a leak happens nobody can prove who typed what. Retrofitting ACLs later means re-plumbing every stream/control path, so it never happens.

## Strlix solution (concrete UX + IA)

**Permissions exist at device-create time, in the phone, not in a separate admin console.**

1. **Create Phone sheet, step 2 = "Who can use it"** — mandatory, non-skippable, default **Private (only me)**. Three presets, phrased in consequences not roles:
   - *Watch only* — sees screen, cannot tap, clipboard/file/OTP redacted.
   - *Operate* — taps/types, no file export, no clipboard copy-out, OTP masked.
   - *Owner* — everything incl. delete + billing.
2. **Grant = capability token, always expiring.** Share sheet has no "never" option; picker is 1h / 8h / 7d / 30d, default 8h. Expiry countdown renders as a pill in the phone's top bar for both parties.
3. **In-phone permission HUD.** A persistent thin strip on the streamed device: `👁 2 watching · Priya (Operate, 3h left)`. Tap → revoke in one tap, stream control channel closes within 2s. Guests see their own limits: "Clipboard export off."
4. **Sensitive-surface guard.** OTP/SMS/password fields, keychain, and file manager are flagged surfaces. For non-Owner, the region is blurred server-side in the encoder and input is dropped, so a screenshot of the guest stream never contains the secret.
5. **Audit is a phone app, not a CSV.** Built-in "Activity" app on every device: scrollable timeline of session start/stop, app launched, file exported, clipboard used, permission changed — each row with actor avatar and a 5s scrubbable clip thumbnail from the recorded stream. Export signed JSON.
6. **AI inside the phone does the ACL work.** The device assistant (bottom-sheet, on-device UI) accepts: "give Priya operate on this phone until Friday, no files." It renders a *diff card* (before → after capabilities) requiring explicit Confirm; AI never applies a grant silently and cannot escalate itself or grant Owner.
7. **Client folders = blast radius.** Devices group into Client spaces; a grant is scoped to a device or a space, and the share sheet shows "This also exposes 4 other phones" in red before confirm.

## Android 7+ / graceful degradation notes

- Guest client on Android 7: HUD and share sheet are plain DOM/CSS (no `backdrop-filter`, no container queries); revoke via full-page fallback route `/access/:deviceId`.
- Redaction is **server-side**, so old WebViews with no overlay compositing still can't see secrets.
- No WebCrypto dependency on client: tokens minted/verified server-side only.
- If WebSocket drops to long-poll, control is disabled (fail closed) rather than unscoped.

## Acceptance criteria

- Creating a phone is impossible without choosing an audience; default is Private.
- No UI path produces a non-expiring grant; expired grant kills control within 2s while video degrades to watch-only.
- A Watch-only or Operate guest requesting `/files`, `/clipboard`, or an OTP screen region gets denied server-side and sees redacted pixels, verified by an integration test against :8789.
- Every grant, revoke, export, and clipboard use appears in the on-device Activity timeline with actor + timestamp within 1s, hash-chained.
- AI grant requests always render a diff card and require human Confirm; AI cannot mint Owner.
