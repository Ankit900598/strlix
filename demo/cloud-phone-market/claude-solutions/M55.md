## Mistake restated
Competitors bolt an AI copilot *outside* the device: a side chat panel that talks about the phone via screenshots and RPC. Users learn "AI is a chatbot that sometimes drives my phone," which is the wrong mental model, kills differentiation, and makes every AI action feel remote and unaccountable. It persists because external LLM attach is trivially monetizable; an agent that actually runs as a resident of the cloud phone (its own app, its own permissions, its own on-screen presence) is real engineering.

## Strlix solution (concrete UX + IA)
Core rule: **the AI has no UI outside the phone frame.** There is no chat sidebar anywhere in web-market.

1. **Agent is an installed app.** In the marketplace grid, `Strlix Agent` appears as a first-class app tile with version, permissions list, and an Install/Update button — same card component as any other APK. Uninstalling it is allowed and visibly disables AI features. This one decision teaches the mental model instantly.
2. **In-frame launcher.** Inside the phone viewport, a small persistent bubble (Android-style overlay, bottom-right, draggable, snaps to edge) is the *only* entry point. Tap → expands to a sheet **rendered inside the device bounds**, never spilling into the web chrome. Everything scales with the device stream's CSS transform.
3. **Actions, not answers.** The sheet defaults to an action list (Install app, Clean storage, Fill this form, Watch for OTP), not a text box. Free text is a secondary tab.
4. **Visible embodiment.** When the agent acts, the user watches the real taps: a ghost-cursor overlay draws each tap/swipe on the stream with a 400ms trail, and a status chip reads "Agent is using Settings." Pointer input from the human is soft-locked (tap anywhere = instant takeover + agent pauses).
5. **Receipts, on-device.** Every agent run writes to an in-phone "Activity" list (screens touched, packages changed, undo where possible), reachable from the bubble — not from a web dashboard.
6. **IA:** `Market → Devices → Device view (stream + bubble) → Agent app page`. Marketplace copy never says "copilot"; it says "installed on your phone."

## Android 7+ / graceful degradation notes
- Overlay bubble is **client-side DOM over the video**, so no `SYSTEM_ALERT_WINDOW` requirement on API 24.
- Agent service targets API 24: no foreground-service type constraints, no scoped-storage assumptions; file ops via SAF fallback on API 29+.
- If Accessibility service is unavailable/denied → agent degrades to "suggest + you tap," showing the highlight ring on the target element instead of tapping.
- No SSE/WS → poll `/agent/status` at 1s; ghost cursor disabled, status chip remains.
- Low-end/2G: overlay renders as static highlight rects (no trail animation); `prefers-reduced-motion` respected.

## Acceptance criteria
- Zero AI affordances exist outside the phone frame; grep of web-market finds no sidebar chat component.
- Strlix Agent is installable/uninstallable from the marketplace grid, and uninstalling hides the bubble.
- During an agent run, ghost-cursor taps align with the actual stream within ~50px, and a human tap pauses the agent within 300ms.
- With Accessibility denied, the agent still completes a "suggest" flow without errors on an API 24 device.
- Payment flow completes end-to-end in test mode with no live credentials present in the repo.
