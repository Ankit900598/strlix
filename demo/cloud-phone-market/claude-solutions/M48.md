## Mistake restated
Competitors render recharge banners, VIP nags, and event popups **inside the stream viewport chrome** — the same rectangle the user is touching to play. Result: mis-taps land on a purchase sheet instead of the game, immersion breaks, and every session has an involuntary ad surface. It persists because the stream is the highest-attention pixel real estate, so growth teams monetize it.

## Strlix solution (concrete UX + IA)
**Hard rule: the stream rect is sovereign.** Nothing renders over `#stage` except (a) session-critical state (disconnect, reconnect, session expiring <60s) and (b) user-invoked UI. Enforced structurally, not by convention:

1. **Two DOM roots.** `#stage-root` (video + input capture) and `#chrome-root` (everything else), siblings, never nested. A dev-mode `MutationObserver` on `#stage-root` throws on any injected node that isn't the video/input layer. CI test asserts it.
2. **Monetization lives in the Tray, outside the rect.** A slim 44px rail below (portrait) / right (landscape) of the phone: `[balance chip] [AI] [clipboard] [files] [⋮]`. Balance chip is passive text — `₹120 · 2h 14m left`. No animation, no red dot for upsell. Red dot is reserved for *functional* events only (file transfer done, APK installed).
3. **Low-balance = degrade, never interrupt.** At 15 min left the balance chip turns amber; at 5 min it pulses *once* and a **non-modal toast docks in the tray** (not over the phone) with "Top up" + "Dismiss". At 0, stream pauses with a full-stage screen — that's allowed, it's session-critical, and it's the only place a pay CTA may appear over the rect.
4. **AI is inside the phone, not an outside chat.** The assistant is an Android-side overlay the *user* summons (long-press the tray AI key or 3-finger tap), drawn by the agent app within the guest OS, so it obeys Android focus/IME rules and never intercepts host clicks. It never markets — `assistant.policy.noCommerce = true`; if a user asks "how do I get more time", it *deep-links* to the tray, doesn't render a buy button.
5. **Notification inbox, not popups.** Events/promos go to `chrome-root` → Inbox panel with an unread count. Zero auto-open. Per-user `promoOptOut` in settings genuinely removes the count.
6. **Mis-click insurance.** Any purchase sheet requires a deliberate second confirm and has a 400ms input-dead-zone on open, so a stray tap can't chain into a charge.

## Android 7+ / graceful degradation notes
- Tray is plain DOM/CSS flex — no `backdrop-filter`, no container queries; fallback solid `#111` panel.
- Chrome 57-era: `IntersectionObserver`/`ResizeObserver` polyfilled or skipped (guard is dev-only anyway).
- No WebRTC datachannel for quota — poll `/session/quota` every 30s over fetch; falls back to WS push when available.
- Landscape with no `env(safe-area-inset-*)`: fixed 44px rail, stage rect recomputed via `resize` listener.
- Toasts use `setTimeout` + CSS transform, not Web Animations API.

## Payment notes

## Acceptance criteria

- Inbox never auto-opens; `promoOptOut=true` yields no badge and no toasts across a full session.
