## Mistake restated
Competitors drop sessions during regional capacity/network incidents and show only a generic "Disconnected — retry" dialog. No public status surface, no incident ID, no ETA, no credit. Users conclude the product is broken (not the region), flood support, and leave 1-star reviews. It persists because a public status page is a permanent, indexable record of downtime that sales must explain away.

## Strlix solution (concrete UX + IA)
Status is **inside the phone**, not a separate marketing site — the phone tells you what happened before you can ask.

1. **Region health chip in the phone shell** (top-right of the device bezel, always visible): green dot `Mumbai · OK`, amber `Mumbai · Degraded`, red `Mumbai · Incident #INC-2026-0921-03`. Tap → incident sheet.
2. **Disconnect = incident sheet, never a bare error.** On socket close, client hits `GET /api/v1/status/region/{region}` before rendering. Sheet shows: cause in plain words ("GPU host pool in ap-south-1 lost network at 14:02 IST"), started-at, live ETA, affected feature list, incident ID copyable, and **three buttons**: `Move me to Singapore (est. 40s)`, `Wait here — auto-reconnect`, `Notify me & close`. Session state (installed APKs, /sdcard) is pinned so a region hop is a restore, not a reset.
3. **Auto-credit, announced not requested.** If downtime > 3 min on a paid plan, sheet shows "We've added 1 day to your plan — no ticket needed. Ref INC-…". Kills the support wave that causes the review spiral.
4. **AI in the phone explains it.** The on-device Strlix assistant surfaces an incident card: "This isn't your network — ap-south-1 is degraded. Want me to migrate you?" One tap executes the migration. No external chat widget.
5. **Public `/status` page** — same JSON feed, SSR'd, indexable, 90-day uptime bars per region, RSS + email subscribe. Publishing it is the point: it converts "Strlix is broken" into "Strlix told me first."
6. **Pre-purchase honesty:** region picker in checkout shows the same health chip + 30-day uptime %, and blocks buying into a red region with "Pick Singapore instead."

## Android 7+ / graceful degradation notes
- Chip + sheet are plain DOM/CSS (no CSS `:has()`, no container queries); Chromium 58 safe, transpile to ES5.
- No `EventSource` polyfill required: `statusClient` feature-detects and falls back to 15s `fetch` polling (XHR shim if `fetch` absent).
- Public `/status` is server-rendered HTML — usable with JS off and readable on 320px screens; uptime bars are `<div>` widths, not canvas/SVG animation.
- If the status API itself is unreachable, show honest neutral state: "Can't reach Strlix status — likely your network" + retry, never a false green.
- Incident text and IDs are selectable/copyable for pasting into support.

## Payment notes
Auto-credits are **plan-time extensions**, not refunds — no charge or refund API call. Stripe/Razorpay stay in test mode; `credits.js` writes a `plan_extension` ledger row keyed by `incidentId+userId` (idempotent), and checkout reads remaining days from the ledger. No real money moves.

## Acceptance criteria
- Any stream disconnect renders `IncidentSheet` with a live region status or an explicit "status unreachable" state — the bare "Disconnected" error path is deleted from the codebase.
- Operator opening an incident propagates to chip, sheet, `/status`, and checkout region picker within 30s.
- "Move me to <region>" restores the session with /sdcard and installed apps intact; failure falls back to wait-and-retry with the same incident ID.
- `/status` renders full 90-day per-region history with JS disabled and on a Chromium 58 / Android 7 device.
- Downtime > 3 min grants exactly one plan extension per user per incident, visible in-sheet and in billing, with zero payment-gateway calls.
