## Mistake restated
now.gg advertises "instant play," then gates it behind interstitial ads, an opaque wait queue ("position unknown, ETA unknown"), and a premium tier whose only concrete benefit is skipping the thing they created. The user pays attention or money to undo an artificial obstacle, learns the headline promise was false, and disputes the charge. It persists because ad impressions + skip-the-queue IAP are the revenue model, so degradation *is* the product.

## Strlix solution (concrete UX + IA)
Principle: **never promise a session we can't start; never sell a queue-skip.**

1. **Pre-tap capacity truth.** Every app card in the market grid carries a live capacity chip from the scheduler, rendered *before* tap: `Ready now` (green), `~40s` (amber, measured p50 from last 20 starts, not guessed), `Full — notify me` (grey). Tapping a grey card never opens a player; it opens a notify sheet. No card ever shows "Play" if the pool can't serve it.
2. **Queue is a contract, not a fog.** If amber, the launch sheet shows position (`3 of 7`), a live countdown, and the phone frame already booting in the background (warm pre-pull of the container image) so the wait is doing real work. A visible **"Leave queue"** button, and an auto-refund-of-nothing guarantee: queue time is never billable minutes. Timer for billing starts on first rendered frame from :8789, not on session-create.
3. **Zero interstitials.** Hard rule encoded in `POLICY.md`: no ad may occupy the path between tap and frame 1. Monetization is minutes + concurrency + persistence, all of which are stated on the card, e.g. `Free: 30 min/day, 1 device, session resets`. Premium buys *more of the same good thing*, never removal of a nuisance.
4. **Paywall states are diegetic.** When free minutes run out, the phone screen itself dims into an in-frame overlay inside the device bezel showing minutes used, exactly what resets at midnight local, and the upgrade delta table. Session state is snapshotted and restorable for 24h — so the paywall never destroys work.
5. **AI inside the phone.** The assistant is a floating bubble over the Android surface, not a site chatbot. On a queue it says "I'll ping you" and can pre-install the APK into the warm container so frame 1 is already at the app's home screen.
6. **Public trust page** `/status`: 7-day p50/p95 time-to-first-frame, queue incidence, refund rate. Linked from footer *and* from the queue sheet.

## Android 7+ / graceful degradation notes
- Stream client feature-detects WebCodecs → falls back to MSE H.264 baseline → falls back to JPEG-over-WS at 15fps. Chip shows `Low-bandwidth mode` honestly rather than stalling.
- No WebGL required for the bezel; CSS-only frame.
- API 24 WebView lacks `ResizeObserver`/`IntersectionObserver` → ship polyfills; capacity polling degrades from SSE to 5s `fetch`.
- If TTFF exceeds 20s, auto-offer "notify me instead" and release the slot — never an infinite spinner.
