## Mistake restated
M54: the cloud phone streams video but drops, mutes, or delays audio relative to input. A tap on a dialer key, a WhatsApp voice note, or YouTube playback lands 300–800 ms off the picture, so calls and media apps read as broken. It persists because encoders are tuned for video bitrate and A/V sync work (PTS alignment, jitter buffer, echo control) is unglamorous engineering.

## Strlix solution (concrete UX + IA)
Audio is a first-class, visible, user-controllable channel inside the phone frame — never a hidden WebRTC track.

1. **Audio pill (in-phone, top-right of status bar overlay)** — always rendered over the device screen, not in a side panel. Three states: `LIVE` (green, shows live 8-bar VU meter driven by `AnalyserNode`), `MUTED` (tap to unmute; also surfaces browser autoplay blocks with "Tap to enable sound"), `LAGGING` (amber, shows measured A/V skew in ms). Tap opens a sheet.
2. **Audio sheet** — Output volume, Mic passthrough toggle (getUserMedia → uplink for calls/voice notes), Sync mode: `Auto | Low-latency (calls) | Smooth (media)`, and a **Resync now** button that flushes the jitter buffer and re-anchors PTS. Show current skew + jitter numerically.
3. **Auto sync policy**: server tags each app launch with a profile. Dialer/WhatsApp/Meet → low-latency (20 ms Opus frames, 40 ms target buffer, video drops resolution before audio ever degrades: audio floor 32 kbps is never reclaimed by video). Netflix/YouTube → smooth (120 ms buffer, video is the master clock, audio resampled ±0.5% to chase).
4. **Skew detection without guessing**: every 2 s the stream server emits an inaudible 18 kHz chirp with a matching video frame marker; client correlates chirp arrival vs marker render and reports skew. If |skew| > 120 ms for 3 samples, client auto-resyncs and the pill flashes `Resynced` for 2 s.
5. **AI inside the phone**: the on-device Strlix assistant (floating bubble) gets an audio-aware action — "Sound is off/laggy" → it runs the resync, switches profile, and speaks/toasts the result in the phone UI. No external chat.
6. **IA**: audio state lives in one store (`audioBus`) consumed by pill, sheet, assistant, and diagnostics — single source of truth, no duplicate mute flags.

## Android 7+ / graceful degradation notes
- Chrome on Android 7 lacks reliable `playoutDelayHint`: fall back to manual buffer target in `avSync.ts`.
- No Opus RED/FEC? Degrade to plain Opus, keep 32 kbps floor.
- Autoplay blocked (all mobile browsers): stream starts muted with pill in `MUTED` + pulsing "Tap for sound"; first user gesture unmutes and resyncs.
- Mic denied: mic toggle shows "Mic blocked — calls will be one-way", downlink audio unaffected.
- No WebRTC / 2G: audio-only mode — video freezes to 1 fps thumbnails, audio keeps full bitrate.

## Acceptance criteria
- Measured A/V skew stays under 80 ms for 95% of samples over a 10-minute call profile session.
