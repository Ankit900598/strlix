## Mistake restated
Competitors ship the stream as an unlabeled `<canvas>`/`<video>` with no keyboard map, no visible focus ring, tab order that dumps you into ad panels before the phone, and connection/session state communicated only by a color dot or a toast. Screen-reader users can't tell if the phone is booting, reconnecting, or dead; keyboard-only users can't press Back/Home/Recents; low-vision users lose the cursor. It persists because demos are driven by a mouse and a11y is never a scored line item.

## Strlix solution (concrete UX + IA)
1. **Stream canvas is a real control.** `role="application"`, `aria-roledescription="Cloud Android phone"`, `aria-label="Pixel 6 · device-3f2a · connected"`, `tabindex="0"`, 3px focus ring outside the bezel. On focus, a screen-reader-only live hint: "Keyboard control active. Press ? for keys, Esc to release."
2. **Keyboard map, discoverable.** `?` (or F1) opens a Key Map sheet, also linked from the toolbar as a visible "Keyboard" button (never mouse-only). Bindings: `Esc` release focus/trap, `Alt+←` Back, `Alt+H` Home, `Alt+R` Recents, `Alt+P` Power, `Alt+↑/↓` Volume, `Alt+S` screenshot, `Alt+/` toggle on-screen key overlay. Arrows/Enter map to Android D-pad so Android's own TalkBack-friendly focus works inside the guest.
3. **Focus order + trap.** DOM order = Skip links → App bar → Device list → **Phone stage** → AI dock → Billing. Two skip links: "Skip to phone stage", "Skip to AI assistant". Focus is *opt-in* trapped: entering the stage captures keys, `Esc` (double-tap guard) releases so Tab never gets swallowed.
4. **Captioned status, not dots.** A `StatusCaption` strip under the bezel with text + icon + `aria-live="polite"` (`assertive` only for disconnect/billing failure): "Booting (12s)", "Reconnecting — attempt 2 of 5", "Session ends in 5 min", "Disconnected — press Enter to reconnect". Same strings feed the dot's tooltip and the a11y log panel (scrollback of last 20 events, so a SR user can re-read missed announcements).
5. **AI inside the phone, accessible.** The in-phone AI dock is a labeled toggle button (`Alt+A`), its transcript is a `log` region; every AI action on the device is announced as text ("AI tapped Settings > Wi-Fi") — which doubles as the a11y caption track.
6. **Settings:** Accessibility tab — reduce motion (kills bezel/parallax animation, honors `prefers-reduced-motion`), high-contrast bezel/focus, larger hit targets (≥44px), caption verbosity (terse/verbose), sticky modifiers for one-handed/switch users.

## Android 7+ / graceful degradation notes
- Guest is Android 7+: send raw keycodes via input channel, no dependency on newer accessibility APIs; TalkBack in-guest is optional and toggled from the panel.
- No WebRTC datachannel → fall back to WebSocket key events; no canvas → `<img>` MJPEG fallback keeps identical `aria-label` and caption strip.
- Touch-only/mobile browsers: on-screen nav bar (Back/Home/Recents) is always rendered, not just a keyboard affordance.

## Payment notes
Checkout is test-mode Stripe/Razorpay stub, no real charges. A11y-relevant: errors rendered as inline text tied via `aria-describedby` (never color-only), card iframe reachable by Tab, and "Payment failed" announced `assertive`.

## Acceptance criteria
- Keyboard-only user can: sign in, pick a device, start a session, press Back/Home/Recents, and end the session — without a mouse; focus visible at every step.
- Screen reader announces stream state changes (boot, connect, reconnect attempts, disconnect, session expiry) within 1s; last 20 events re-readable in the a11y log.
- `?`/toolbar Keyboard button lists every active binding, generated from `keymap.ts`; no handler exists that isn't listed.
- axe-core CI run: zero critical/serious violations on market, device, stage, and checkout pages; stage canvas has a non-empty accessible name.
- `prefers-reduced-motion` and high-contrast modes remove animation and meet 3:1 focus / 4.5:1 text contrast.
