## Mistake restated
Farm consoles wrap the device in permanent DevTools/logcat/network/Appium panes. The phone becomes a thumbnail inside an IDE; every session starts with chrome, not with the app under test. It persists because QA buyers explicitly requested each pane, and nobody ever removes one.

## Strlix solution (concrete UX + IA)
**Phone is the document; tools are a drawer.**

1. **Default state = bare phone.** Device fills viewport height (`min(100dvh - 88px, 16:9 aspect)`), centered, zero side panels. Only a 44px top strip: device name, battery/net pill, `⌘K`, session timer, End.
2. **Tools live behind one affordance: the Inspect Rail.** A single 36px vertical tab on the right edge labeled with a count badge (e.g. "3 signals"). Click/swipe-left opens an overlay sheet *over the background*, never resizing the phone — the phone shrinks at most 0 px on ≥1280px screens (sheet floats), and on smaller screens the sheet covers 70% as a bottom sheet.
3. **Signals, not streams.** Instead of a raw logcat wall, the rail shows AI-summarized *signals* from the in-phone agent: `ANR 4.2s in CheckoutActivity`, `3 failed requests to /pay`, `OOM warning`. Each expands to the raw log/HAR lines. Raw firehose is one click deeper (`Show raw logcat`), and is never the default tab.
4. **AI is inside the phone.** A floating Strlix bubble *on the device canvas* (draggable, snaps to edge). Tap → in-phone command sheet rendered over the screen: "record this flow", "why did that crash", "run on 5 more devices". Output lands as a signal card, not a chat sidebar.
5. **Appium/ADB become a URL, not a pane.** A "Connect your tools" popover gives the WebDriver endpoint + token + `adb connect` line, copyable. No embedded terminal. Power users run tools locally where they already live.
6. **Sticky per-user, not per-product.** Rail open/closed state persists in `localStorage` per workspace; a QA lead who wants panes open always gets them, a PM never sees them. Ship default = closed.
7. **Focus mode** (`F`): hides top strip too, phone only, ESC restores.

## Android 7+ / graceful degradation notes
- Stream: WebRTC H.264 baseline first; fall back to MJPEG-over-WS from `:8789` when `RTCPeerConnection` or hardware decode is absent (Android 7 WebView, old Chrome). Rail/UI identical in both paths.
- `dvh` → `vh` fallback via `@supports`; `backdrop-filter` on the sheet degrades to solid `#11131A`.
- Low-end/`≤360px` viewport: rail tab collapses to a single badge in the top strip; sheet becomes full-screen with a back arrow. AI bubble auto-snaps to avoid the nav bar inset.
- If signal ingestion fails, rail shows "Raw logs only" — phone stream never blocks on it.

## Acceptance criteria
- On first load of a session, zero tool panes are visible; the phone occupies ≥70% of viewport height on a 1440×900 display.
- Opening the Inspect Rail does not change the phone's rendered pixel dimensions on ≥1280px viewports (assert via ResizeObserver test).
- Appium/ADB access is provided only as copyable endpoint + token; no embedded terminal or network waterfall ships in v1.
- Rail default-closed for new users, persisted per workspace after the first manual toggle.
- With WebRTC disabled, MJPEG fallback renders and all rail/AI controls remain functional on Android 7 Chrome 60.
