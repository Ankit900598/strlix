## Mistake restated
VSPhone-style billing splits one job ("get more phone-time") across four incompatible objects: wallet balance, activation/redeem codes, VIP tier upgrades, and dangling "unpaid order" records. Each has its own screen, its own failure mode, and its own support ticket ("code invalid", "paid but no VIP", "wallet won't convert"). It persists because resellers buy code batches at wholesale, so codes can't just be deleted — but the user shouldn't pay for that.

## Strlix solution (concrete UX + IA)
**One meter, many funnels.** Everything credits a single unit: **Phone Minutes** (plus device-slot entitlement). Wallet, code, VIP, and card checkout are *inputs* to the same meter, never parallel currencies.

1. **In-phone Top-Up sheet** — a bottom sheet rendered *over the live stream* (phone stays running, never a separate web portal). Triggered by tapping the minutes chip in the phone's status bar, or auto-raised at 10 min remaining as a non-blocking toast.
2. **Single input field, auto-detecting.** One box: "Code, voucher, or paste order ID". Paste `STRLIX-XXXX-XXXX` → redeem; paste an order ID → resumes/cancels that order inline. Below it: one primary button **"Add minutes — ₹/$ card"**. That's the whole IA. No VIP page.
3. **VIP is derived, not purchased.** Tier = rolling 30-day minutes consumed. Shown as a passive badge with "Silver → Gold at 800 min". Removes the "upgrade" path entirely; removes "paid but not VIP" tickets.
4. **Unpaid orders can't exist.** Orders are created only on payment-intent success; anything else is a 15-min held quote that self-expires and is surfaced as a dismissible banner, not an account state.
5. **Reseller codes preserved, hidden.** `/r/:partner` landing pre-fills the code field; partner margin lives server-side in the code's minute value. Agents get a separate `/partner` batch console — never mixed into consumer UI.
6. **Failed redeem is self-healing.** Error copy names the cause (expired / already used / wrong region) and offers one tap: "Use card instead (keeps your 30 min free trial)".

## Android 7+ / graceful degradation notes
- Sheet is plain DOM + CSS transform, no `dialog`/`backdrop-filter` (Chrome 53 lacks both); fall back to a fixed-position div with solid `rgba` scrim.
- No `Intl.NumberFormat` currency-display options — format prices server-side into display strings.
- If WebSocket drops, meter falls back to 30s polling; never blocks the stream.
- Payment sheet opens in a full-page redirect on WebView <60 (popup blocked), returning to `/phone?resume=1`.

## Acceptance criteria
- Every purchase path (card, code, partner link) results in one ledger entry with the same `minutes` unit; no second balance exists in the UI.
- Top-up completes without leaving the phone stream; stream never pauses.
- Redeeming an invalid code shows a specific reason plus a one-tap card fallback; redeeming the same code twice is idempotent.
- No screen, route, or button in `web-market/` contains the word "VIP upgrade" or exposes an unpaid-order state.
- Works on Android 7 WebView: sheet opens, minutes update, redirect checkout returns to the running phone.
