## Mistake restated
Competitors meter raw device-minutes: a small included bundle, per-minute overage on top, and free tiers that hard-kill a session after a few minutes. The user's clock is running during app install, ADB waits, cold boot, and thinking time — so cost is unpredictable and a demo can die mid-flow. It persists because per-minute billing tracks GPU/ARM cost exactly, but it taxes the exact behavior (exploration) the product needs.

## Strlix solution (concrete UX + IA)
1. **Bill *active* minutes, not wall-clock.** A `MeterState` machine in the stream client: `ACTIVE` (input in last 90s or video frames changing) → billed; `IDLE` (no input 90s) → unbilled, phone frozen-but-warm for 10 min; `PARKED` → snapshot to disk, 0/min, resumes in <8s. Boot, APK install, and snapshot restore are never billed — shown as `Free: warming up` on the meter.
2. **Meter lives *inside the phone chrome*, not in a settings page.** A thin pill above the device frame: `18:42 active · 41 min left today`. Tap → breakdown sheet (active / idle-free / install-free). Turns amber at 80%, never a modal over the screen.
3. **No mid-flow kill.** At 100% of the plan the session enters **Grace Mode**: 10 extra free minutes, banner `Grace: 9:12 — finish your flow`, and the AI offers "Save session → resume later" (snapshot + shareable resume link). Free tier gets 20 active min/day, grace included; it *pauses*, never terminates.
4. **Hard spend ceiling, default on.** Prepaid minute packs only, no invoiced overage. `Auto-stop at ₹0 remaining` is the default toggle; opt-in auto-topup is explicit and capped per month. Price surface shows one number: minutes, not $/min.
5. **AI inside the phone reduces the meter.** The in-phone assistant overlay does long waits headlessly ("install this APK, log in, wake me at the home screen") — those agent-executed steps are billed at the idle rate, so delegating is visibly cheaper. AI shows `this will use ~3 active min` before running a task.

## Android 7+ / graceful degradation notes
- Meter pill is plain DOM over the canvas — no WebGL/backdrop-filter dependency; falls back to solid background on Chrome 51+.
- Idle detection: prefers frame-diff via `requestVideoFrameCallback`; on older WebViews falls back to input-event-only idle timing (pointer/key/touch), which is conservative in the user's favor.
- If WebSocket drops, client keeps a local ledger and stops accruing after 30s of silence; server reconciles on reconnect and never bills disconnected time.
- No `Intl.NumberFormat` unit formatting; minutes rendered manually.

## Payment notes
Test-mode only. Stripe test keys / Razorpay test stub behind `BILLING_MODE=test`; top-ups create a fake `pack_*` grant and log to `ledger.jsonl`. UI shows a persistent `TEST MODE — no card charged` strip on the top-up sheet. No stored PAN, no webhooks to production.

## Acceptance criteria
- A session left untouched for 5 minutes accrues 0 billed minutes; meter shows the gap as `idle (free)`.
- APK install and cold boot appear on the breakdown sheet as free and are excluded from the billed total.
- Hitting the plan limit mid-flow shows Grace Mode with a countdown and a working resume link; the stream is never torn down without user action.
- Balance reaching zero with auto-stop on parks the device (snapshot) rather than deleting it; resume restores the same app state in under 8s.
- On an Android 7 WebView, the meter pill renders and idle detection still works via input events.
