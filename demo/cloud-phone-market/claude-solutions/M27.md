## Mistake restated
Free tiers enforce a hard wall-clock cap (e.g. "session ends in N minutes") and then destroy the VM. The user's installed APK, logged-in test account, app state, scrcpy scroll position, and half-finished QA repro are gone. The cap itself is defensible (always-on free devices get abused for farming/mining); the *data loss* is not. Vendors keep it because snapshotting costs disk and nobody wants to store 4GB/user of free-tier garbage.

## Strlix solution (concrete UX + IA)
Separate **compute time** (metered, capped) from **device identity** (persisted, cheap). The cap ends the *stream*, never the *phone*.

1. **Phone is a persistent object, session is not.** Every free user gets up to 2 "Saved Phones" in a `Shelf` IA node. A phone has: installed APK list, `/data/data` delta for user-installed packages only, accounts, screen density/locale, clipboard. Not the base system image — that's shared/dedup'd. Realistic delta: 40–300MB, not 4GB.
2. **Auto-freeze, not kill.** At T-120s the in-phone AI overlay (a floating pill inside the device frame, bottom-right, not a sidebar chat) says: *"Freezing in 2:00. Everything stays."* Buttons: `Freeze now`, `+10 min (test-mode upgrade)`. At T-0 we run the freeze path: `am broadcast` a quiesce, `pm list packages -3` + tar the user-data delta, snapshot to object storage, tear down compute.
3. **Freeze receipt.** On the market page, the phone card flips to `Frozen · 4m ago` with a thumbnail of the last frame and a `Resume` button. Resume boots base image, re-applies delta, restores last-foreground activity via the recorded `component/name`. Target <25s; show a restore progress inside the phone frame, not a blank spinner.
4. **QA Timeline.** The AI overlay keeps an append-only session log (installs, crashes from logcat `FATAL EXCEPTION`, taps on marked elements). This survives freeze and is the thing users actually fear losing. `Export .md` works even while frozen — no compute needed.
5. **Honest cap copy.** `35 min/session · 3 sessions/day · 2 saved phones` shown *before* launch, on the app card, so nobody is surprised mid-repro.
6. **Abuse control without data loss:** cap concurrency (1 live phone/account), idle-detect (no input 90s → freeze early, refund remaining time), delta size ceiling 500MB (over → prompt user to prune, keep APK list only).

## Android 7+ / graceful degradation notes
- Delta capture uses `run-as`/tar over adb, not `bu backup` (deprecated 7–12, removed later); on API 24–25 fall back to **APK-list-only restore** and label the card `Apps restored, data not` — explicit, not silent.
- No `MediaProjection` for the freeze thumbnail on old targets → use last decoded stream frame client-side, downscale to 320px WebP.
- If WebRTC/H.264 unavailable, stream degrades to MJPEG at 8fps; freeze/resume logic is transport-independent.
- Restore target activity via `am start -n` with `--activity-clear-task`; if the recorded component is gone, land on launcher and say so.

## Acceptance criteria
- Hitting the 35-min cap produces a frozen phone with a thumbnail; zero user-visible data loss for user-installed apps on API 26+.
- Resume restores installed apps, app data delta, and last foreground activity in <25s p50 on a warm base image.
- QA Timeline is readable and exportable while the phone is frozen, with compute torn down.
- Caps and saved-phone quota are visible on the app card before the first launch, and a T-120s warning always fires.
- API 24–25 degrades to APK-list restore with an explicit on-card label, never a silent empty phone.
