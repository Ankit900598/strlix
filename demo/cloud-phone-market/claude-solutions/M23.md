## Mistake restated
BlueStacks X markets "play instantly in the browser," but the funnel keeps routing users to a full App Player download (large installer, x86 emulator, Windows-only). The instant-browser promise becomes bait: users who clicked "Play" discover a 500MB gate, and the hybrid model exists to push hardware cost onto the user, not to serve them. Result: broken trust, dead ends on Android/Mac/Chromebook, and a cloud tier that feels like a demo for the installer.

## Strlix solution (concrete UX + IA)
**Rule: browser stream is the only default path. No installer link exists above the fold, ever.**

1. **One button, one outcome.** App card CTA is `▶ Play now` → allocates a session and begins streaming in ≤8s. No modal, no OS sniff, no "for best experience download…" interstitial.
2. **Native install is a *result*, not a gate.** Inside the running phone, the AI assistant (bottom sheet, in-frame — not a side chat) surfaces after ~10 min of session time: *"You've played 10 min. Want this on your own device? I can push the APK to your phone via QR."* This is a sideload handoff for the *user's real Android device*, never a desktop emulator.
3. **Session continuity, not install-for-retention.** Retention comes from persistent device state: `/device/:id` keeps your installed apps, logins, and saved data warm for 7 days on free tier, 30 on paid. Show "Your phone — 4 apps, last used 2h ago" on home. That's the retention hook replacing local install.
4. **IA:** `/` (catalog) → `/app/:slug` (details + Play now) → `/play/:sessionId` (fullscreen stream, AI sheet in-frame) → `/device` (my cloud phone) → `/account`. No `/download` route in nav. A `/native` page exists but is only linked from in-session AI and footer.
5. **COGS honesty:** free tier = 20 min/day, 720p30, idle-kill at 90s no-input, with a visible session timer chip. Degrade quality before degrading access.

## Android 7+ / graceful degradation notes
- Probe order: WebRTC H.264 → WebRTC VP8 → WS JPEG frames at 480p20. Android 7 Chrome 60+ lacks reliable VP9/AV1; never negotiate them.
- No WebCodecs dependency; feature-detect and fall back.
- Touch: Pointer Events with `touchstart` fallback for Android 7 WebView.
- If probe fails entirely, show "Low-bandwidth mode" (480p, frame-drop tolerant) — still in-browser. Never convert a failed probe into a download prompt.
- Wake-lock optional; degrade silently if unsupported.

## Acceptance criteria
- No route, button, or modal in the default funnel links to a desktop installer; `/download` returns 404.
- First `Play now` click reaches visible first frame in ≤8s on a 10 Mbps connection.
- On Android 7 / Chrome 60, stream falls back to WS-JPEG and remains interactive — no download prompt on failure.
- Native handoff UI appears only after ≥10 min cumulative session time, and offers an APK QR for the user's own phone, never a PC emulator.
- Returning user sees their warm device with prior installs intact; upgrade prompt extends the live session without reconnect.
