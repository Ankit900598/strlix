## Mistake restated
Competitors ship a bilingual shell, not a bilingual product: chrome is translated, but deep surfaces (error toasts, ADB/stream failure reasons, invoice lines, help-article *bodies*, agent replies) fall back to Chinese or render empty. An EN user hits a wall mid-task (payment failure, stream reconnect, KYC) and files a ticket. It persists because EN is measured by page-count, not by task-completion, and because help content has no per-locale publish gate.

## Strlix solution (concrete UX + IA)
1. **One locale bus, phone-first.** Locale is resolved once (`?lang` → account pref → `navigator.languages` → `en`) and injected into: React UI, the in-phone AI agent system prompt, desktop-api `:8789` request headers (`X-Strlix-Locale`), and the Android container's `persist.sys.locale` + IME default. The phone itself boots in the user's language — no "English website, Chinese phone".
2. **Machine-readable errors, never server prose.** `:8789` stream/control endpoints return `{code:"STREAM_WEBRTC_ICE_FAIL", params:{region:"sg"}}`. The client owns all strings. A missing key renders `⟨STREAM_WEBRTC_ICE_FAIL⟩` in a dev-visible badge + auto-reports to `/i18n/miss` — never a raw CN sentence.
3. **Help center: body-gated IA.** Article index is filtered by `bodies[locale].status === 'published'`. An article without an EN body is *not listed*; it appears only under "Also available in 中文" with an inline machine-translated body labeled "Auto-translated — verify steps". No more clickable dead ends.
4. **AI inside the phone answers help queries.** The floating agent bubble (inside the device frame) does RAG over locale-published docs only; if the answer exists only in CN, it translates and says so, then offers "Open ticket in English".
5. **Pseudo-locale `en-XA`** (`[!! Ŕéśťářť ƥħöñé ‥‥]`) toggled by `?lang=en-XA` exposes hardcoded strings and clipped CJK-width layouts during review.
6. **Locale-aware formatting** for currency/date/duration via `Intl`; RTL-ready (`dir` attr, logical CSS props) even if `ar` is not launched.

## Android 7+ / graceful degradation notes
- API 24 containers: set locale via `persist.sys.locale` at container boot (no `LocaleManager`, that's API 33+). Fallback to `am start` with `Settings.ACTION_LOCALE_SETTINGS` if the prop write fails.
- Older WebViews lack full `Intl` + `Intl.PluralRules`: ship `@formatjs` polyfills loaded only when `typeof Intl.PluralRules === 'undefined'`.
- If WebRTC is unsupported, degrade to MJPEG-over-HTTP from `:8789`; the degradation banner is a localized key, not a server string.
- Missing CJK/emoji glyphs on minimal Android 7 images: bundle Noto Sans CJK subset; otherwise tofu in the phone's own UI.

## Acceptance criteria
- `scripts/i18n-audit.mjs` fails CI on: key parity gaps, any CJK codepoint in `en.json`, or a help article listed in EN without a published EN body.
- Zero server-originated user-visible prose: every `:8789` non-2xx path renders from a client key (verified by a test that asserts no CN chars in the DOM under `lang=en`).
- End-to-end EN task completion: launch phone → stream error → recover → open help article (full body) → test-mode checkout, with no locale fallback event logged.
- `?lang=en-XA` renders every screen with no untransformed literals and no layout overflow at 360px.
- Phone container locale matches web locale within 2s of switching, confirmed via `/device/locale` readback.
