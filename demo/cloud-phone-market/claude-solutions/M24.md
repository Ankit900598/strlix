## Mistake restated
Competitors gate the cloud device to a partner-signed catalog: you can only launch titles they licensed, and arbitrary APK install is blocked outright. The product stops being "a phone in the cloud" and becomes a game streaming channel. It persists because sideloading creates licensing exposure, malware/abuse surface, and unbounded storage/egress cost — but the fix is *governance*, not prohibition.

## Strlix solution (concrete UX + IA)
Make "Install anything" the default path, with risk tiers instead of a whitelist.

**Three install lanes, all surfaced in one phone-side sheet** (opened by the in-phone Strlix key, never an outside chat window):
1. **Catalog** — curated, 1-tap, pre-warmed image, instant play.
2. **Store account** — user signs into their own Play/third-party store inside the session; purchases are theirs, licensing stays with the user.
3. **Sideload APK** — drag-drop onto the stream canvas, paste a URL, or `strlix push` from desktop. File lands in the session's `/sdcard/Download` via the existing desktop-api upload channel.

**Trust gate (replaces the block):** on sideload we run a fast static scan (hash lookup, signature/cert age, permission diff) and show a one-screen verdict card *rendered inside the phone frame*: cert subject, requested dangerous perms, VirusTotal-style hash verdict, size. Buttons: **Install**, **Install in Sandbox Profile**, **Cancel**. Unknown-publisher APKs default to Sandbox Profile (separate Android user profile, no contacts/SMS/clipboard bridge, network egress metered and capped).

**Cost control without lock-in:** sideloaded state lives in the user's persistent volume with a per-plan quota meter shown in Settings → Storage; cold-start warm images only exist for Catalog titles, so sideloaded apps get an honest "first launch is slower" chip rather than being refused. Egress budget bar in the session HUD.

**AI inside the phone:** the Strlix assistant overlay can be asked "install this APK and tell me what it wants" — it reads the verdict card and speaks the permission summary; it can also do "find the arm64 build of X" and hand back a URL into the same trust gate. It never leaves the device frame.

## Android 7+ / graceful degradation notes
- API 24–25: no `--user` sandbox on some images → hide "Sandbox Profile", show "Isolated session" (ephemeral container, wiped on exit) instead.
- API 24–25: `pm install` only; no session installer split-APK support → reject `.apks`/`.xapk` with a clear "split bundles need Android 9+" message, offer base-APK extraction.
- No `aapt2` on device → inspection runs host-side on the uploaded file; if that fails, show verdict card in "unverified" state and force Sandbox/Isolated default.
- Slow links: upload resumable by chunk; drag-drop degrades to a plain file input.

## Payment notes
Not central. Storage/egress overage upsell uses a Stripe **test-mode** checkout stub (`pk_test_…`, no live keys, no real charges); the quota meter links to it. In-app purchases inside sideloaded apps are the user's own store account — Strlix never proxies them.

## Acceptance criteria
- A user can install an arbitrary, non-partner APK from drag-drop, URL, and desktop push, and launch it in the same session.
- Every sideload shows a trust card with cert subject, dangerous-permission list, and hash verdict before install; unknown publishers default to sandbox/isolated.
- Catalog titles still launch in one tap with pre-warmed images; sideloaded apps launch with an explicit slower-cold-start indicator, never a refusal.
- Storage and egress meters are visible in-session and block only at plan quota, with a test-mode upgrade path.
- On an API 24 device image, unsupported lanes degrade with an explanatory message — no dead buttons, no silent failure.
