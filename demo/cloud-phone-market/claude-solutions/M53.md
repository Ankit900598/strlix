## Mistake restated
Competitors build device pickers and checkout fields as `div`-based custom widgets: no `tabindex`, no arrow-key roving, no `aria-expanded`/`aria-activedescendant`, no typeahead. Modals render without focus containment or restore, so keyboard/screen-reader users either get lost behind the overlay or tab into the dead page underneath. Net effect: a keyboard-only or TalkBack user cannot pick a device plan or complete payment. It persists because teams ship a generic component kit and never run an a11y audit on the two flows that actually take money.

## Strlix solution (concrete UX + IA)
1. **Native-first primitives.** Region/OS/RAM/plan pickers are real `<select>` where the option list is flat and short (≤12). Only the *device model* picker — which needs thumbnails, Android level badge and "stream ready" status — becomes a custom combobox, built to ARIA APG 1.2 *combobox-with-listbox*: `role="combobox" aria-expanded aria-controls aria-activedescendant`, Down/Up/Home/End/PageUp/PageDown roving, Enter/Space commit, Esc revert-and-close, printable-char typeahead with a 700 ms buffer, click and touch parity.
2. **AI stays inside the phone.** No external chat sidebar competing for focus. The in-phone assistant is reachable only from the device frame via a labelled `<button>` "Assistant (Alt+A)"; it never auto-steals focus mid-checkout and announces suggestions in an `aria-live="polite"` region, never `assertive`.
3. **Checkout as a page, not a modal.** `/checkout` is a routed page with `<h1>`, a `<form>`, real `<label for>`, `autocomplete="cc-number cc-exp cc-csc postal-code"`, `inputmode="numeric"`. Errors use `aria-describedby` + `aria-invalid`, summarised in a top error list whose first item receives focus on failed submit.
4. **One shared dialog implementation.** When a dialog is unavoidable (plan comparison, 3DS test step), use `<dialog showModal()>` with a JS fallback: focus moves to the dialog heading, Tab cycles only inside it, Esc closes, focus returns to the invoking element, background gets `inert` (polyfilled).
5. **Stream frame is skippable.** The `:8789` canvas/video lives in a `role="application"` wrapper preceded by a "Skip phone stream" link, so keyboard users never get swallowed by key capture; key forwarding activates only after explicit Enter on "Take control", exits on Esc, state announced live.
6. **Visible focus everywhere:** `:focus-visible` 2px outline + 2px offset, ≥3:1 against both surfaces, never removed; all interactive targets ≥44 px.

## Android 7+ / graceful degradation notes
- `<dialog>` and `inert` are absent on Android 7 WebView → load `dialog-polyfill` + focus-trap fallback; detect via `'showModal' in HTMLDialogElement.prototype`.
- `:focus-visible` unsupported → PostCSS emits `:focus` fallback so focus is *visible*, never invisible.
- No WebRTC/H.264 on old WebView → checkout and picker still work; stream area degrades to MJPEG-over-HTTP from `:8789`, then to a static screenshot + "Open in app" with identical keyboard semantics.
- TalkBack on Android 7 mishandles `aria-activedescendant` → pair it with an off-screen `aria-live` announcing "Pixel 6, Android 12, option 3 of 12".
