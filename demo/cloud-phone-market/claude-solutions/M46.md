# M46 — Data retention & factory reset

## Mistake restated
Competitors hide "recycle"/reset behind activation-code docs or support tickets. Users can't see **what data persists**, **where**, or **how long**, and can't self-serve a clean wipe. Residual state (accounts, cookies, /sdcard) is both a PII liability and a deliberate lock-in: your stuff lives on their disk, so you stay.

## Strlix solution (concrete UX + IA)
**1. In-phone, not in-portal.** A persistent **Privacy pill** in the phone frame's status bar shows a data badge: `↯ 2.1 GB · 14d`. Tap → **Data & Reset sheet** slides up *over the stream* (no page nav, keeps session alive).

**2. Data & Reset sheet** (3 tabs):
- **What's stored** — itemized, byte-accurate: `Apps 1.4 GB · App data 480 MB · /sdcard 210 MB · Clipboard 12 KB · Screenshots 4 · Accounts: 2 signed in`. Each row has a per-row `Wipe` link (wipe just clipboard, just downloads).
- **Retention** — plain sentence at top: *"When this phone is stopped, its disk is deleted in **24h** unless you pin it."* A `Retention` selector: **Ephemeral (destroy on stop)** / **24h** / **Persist until I delete**. Default for trial = Ephemeral. Selector shows the storage cost delta inline.
- **Reset** — two buttons, never buried:
  - `Soft reset` — clears app data + accounts, keeps installed apps. ~8s.
  - `Factory reset` — destroys the disk image, reboots to first-run. Typed confirm (`RESET`), 10s undo countdown toast, then irreversible.

**3. Reset receipt.** After wipe, an in-phone card: *"Wiped 2.1 GB at 14:03 UTC. Disk image `d-8f2a` destroyed. Nothing retained."* with a `Download receipt (JSON)` — signed, exportable for compliance.

**4. AI inside the phone.** The on-device assistant overlay accepts *"delete everything from my banking app"* → it resolves to a scoped wipe plan, previews the exact rows, and requires the same typed confirm. It never wipes silently.

**5. Session end guard.** Closing the tab on an Ephemeral phone shows a one-line interstitial: `This phone will be destroyed. [Keep 24h] [Destroy now]`.

## Android 7+ / graceful degradation notes
- Usage itemization uses `du`/`StorageStatsManager`; on API 24 (no per-UID stats), fall back to coarse buckets (`Apps / Data / Storage`) and label it *approximate* rather than showing fake precision.
- Soft reset on 7.x uses `pm clear` per package loop (no `resetPreferences`); show per-package progress since it's slower.
- No typed-confirm keyboard on small viewports → swipe-to-confirm rail as equivalent friction.
- If `/disk` 5xx or times out: pill shows `↯ —`, sheet still opens, **Reset stays enabled** (never gate destruction on telemetry).
- No WebRTC / low bandwidth: sheet is plain DOM, works in the fallback MJPEG view.

## Payment notes
Retention tiers touch billing: **Persist until I delete** adds a metered storage line. Use test-mode Stripe (`pm_card_visa`) / Razorpay test keys — show a `TEST MODE` ribbon on the confirm dialog and log intents to `desktop-api/routes/billing.stub.ts`. No real charges. Downgrading to Ephemeral must **never** auto-destroy data; it schedules destruction at next stop with an emailed 1h warning.

## Acceptance criteria
- Factory reset reachable in **≤2 taps** from any live phone screen, with zero page navigation and no docs lookup.
- Retention policy and remaining TTL are visible as literal text (`destroyed in 23h 14m`) before any reset action.
- Post-reset, a fresh login shows **zero** prior accounts, clipboard, `/sdcard` files, or app data; verified by an automated E2E that seeds artifacts then asserts absence.
- Every reset produces a downloadable signed receipt; abort within the 10s window leaves data fully intact.
- Disk-usage API failure degrades to an approximate/unknown badge without disabling reset.
