## Mistake restated
Specs (RAM / ROM / Android version / CPU cores / GPU / resolution / region) are inconsistently exposed: some SKUs print them in a price-HTML blob, some omit them, and filters cover only a subset. Buyers pick a plan that can't run their target app (e.g. a game needing Android 7 ARM, or an app refusing Android 13), then demand refunds. It persists because a normalized spec schema makes margin ladders comparable across tiers.

## Strlix solution (concrete UX + IA)
1. **One canonical `DeviceSpec` record, no free HTML.** Every SKU must supply: `ram_mb`, `rom_gb`, `android_api` (int) + `android_label`, `arch` (arm64/x86_64-translated), `cores`, `gpu_mode` (swiftshader|vgpu), `resolution`, `dpi`, `region`, `root` (bool), `gapps` (bool), `magisk`, `persist` (bool). Rendering is schema-driven; a missing field blocks publish (CI lint), never renders "—".
2. **Spec chip row on the phone frame itself.** Inside the device viewport's top bezel strip: `4GB · 64GB · A9 · arm64 · 720p`. Tap → spec sheet sheet-modal. Same chips repeat identically on card, compare drawer, checkout line item, and post-purchase device header — one component, `<SpecChips spec=… density=…>`.
3. **Filters = the schema.** Faceted sidebar auto-generated from the enum/range union of live inventory: RAM slider, ROM slider, **Android multi-select including legacy (5.1/7.1/9)**, root toggle, GAPPS toggle, region. Every facet shows live counts; zero-count values are shown greyed, not hidden (inventory transparency).
4. **"Will my app run?" AI, inside the phone.** In-phone assistant tab: user types/pastes an app name or uploads an APK → parse `minSdk`/`targetSdk`/`native-code` ABIs from the manifest → returns "Runs on: A9-4GB, A7-2GB · Blocked on: A13 (targetSdk gate)" with one-tap filter apply. No external chat window.
5. **Compare drawer** (up to 3 SKUs) diffs the spec table, highlighting only differing rows — makes VIP ladders legible instead of hidden.
6. **Checkout spec lock.** Order summary restates the exact spec; a `spec_hash` is stored on the order. If provisioning would deliver a different spec, purchase is refused, not silently substituted.

## Android 7+ / graceful degradation notes
- Market UI target: ES2017 build, no optional chaining in shipped bundle, `core-js` polyfills; Chrome 60 / WebView 60 baseline.
- Spec chips are plain flex + text — readable with CSS Grid absent; sheet-modal falls back to a full-page `/sku/:id/specs` route if `dialog` unsupported.
- APK manifest parsing needs `DataView`+`fetch`; if unavailable, assistant degrades to a name-based lookup table server-side.
- Stream overlay uses absolute-positioned DOM, not canvas compositing, so it survives MJPEG fallback on old WebView.
