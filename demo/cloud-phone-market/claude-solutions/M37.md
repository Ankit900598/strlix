## Mistake restated
Competitors ship key mapping as a game-only feature buried behind help-center articles. A desktop user who opens a cloud phone, clicks a text field, and types gets nothing (or wrong chars), and never learns a mapping editor exists. The capability is real; discovery, defaults, and writing are not.

## Strlix solution (concrete UX + IA)
1. **Typing works with zero setup.** On desktop, focusing any Android text field (detected via `ime_show` event from the stream agent) auto-attaches a hidden `<textarea>`; keystrokes go over the existing :8789 WS as `{t:"text",s:"..."}` / `{t:"key",code:"Backspace|Enter"}`. IME composition (`compositionstart/end`) sends committed strings, so CJK/Hindi work. No mapping needed for text — mapping is only for touch emulation.
2. **First-keystroke teaching moment.** The first time a user presses WASD/arrow/space while no text field is focused, a bottom-sheet toast appears in-phone-frame: *"Keys aren't touches yet. Turn on Key Controls?"* → [Enable] [Not now] [Never]. Enable opens the overlay editor with a per-app preset already applied.
3. **Key Controls overlay editor** (`Ctrl+K`, and a persistent keyboard glyph in the phone's right-side toolbar — always visible on desktop, not hidden in a menu). Drag chips (WASD stick, tap key, swipe key, repeat-tap) onto a live translucent screenshot of the running app. Saved per `packageName` in the user profile; synced.
4. **AI inside the phone, not an outside chatbot.** The Strlix assistant lives as a floating bubble on the Android surface. Tapping it during the editor gives: *"Auto-map this screen"* — it screenshots the app, detects buttons, and proposes a mapping the user accepts/edits. Also answers "how do I type Hindi here" with an in-frame highlight of the control, never a help-center link.
5. **IA:** Phone toolbar → Keyboard glyph → {Type mode (default) | Key Controls | Presets | Reset}. A one-line status chip under the phone reads "Typing → text field" or "Keys → touch map (Fortnite preset)" so state is never ambiguous.
6. **Presets library** shipped with the marketplace app listing: any app detail page shows "Key controls included" badge; installing applies the preset automatically.

## Android 7+ / graceful degradation notes
- Android 7 lacks some `InputMethodManager` hooks: fall back to `adb shell input text` for ASCII and `input keyevent` for control keys; non-ASCII falls back to clipboard-paste injection (`adb shell am broadcast` clipboard set + `Ctrl+V` keyevent).
- No touchscreen/pointer on device profile → key mapping degrades to tap-only chips (no multi-touch stick); show "Stick needs multi-touch, using D-pad taps."
- Mobile/touch browsers: hide Key Controls entirely, keep native soft keyboard; mode chip hidden.
- No WebSocket/low bandwidth: editor still works offline on last frame; saves queue and flush on reconnect.
