## Mistake restated
Competitors expose "one-click root / Magisk" as a plain help-center toggle with no consequence UX. Enabling it silently fails Play Integrity (and vendor attestation), so banking, UPI, DRM video, and some social apps stop launching or refuse login. The user blames the cloud phone ("your device is broken") instead of the root state. It persists because root is the headline feature for farming/automation buyers, and honest warnings depress activation.

## Strlix solution (concrete UX + IA)
Root is **not a help-center toggle**. It's a **device profile chosen at instance creation**, reversible only by reset, and visible forever in the phone UI.

1. **Two named profiles at create time** (card picker, no default preselected):
   - **Verified Phone** — Play Integrity `MEETS_DEVICE_INTEGRITY` targeted, no root. Badge: green shield.
   - **Developer Phone (rooted)** — Magisk + adb root + Frida hooks. Badge: amber wrench.
   Each card lists a concrete **"Will likely break"** list rendered from `integrity-impact.json` (bank/UPI category, DRM playback drops to SD, some MDM logins). No prose warnings — a table of app *categories*, not brand names.
2. **Typed confirm**: to pick Developer Phone the user types `ROOTED` in a field. Stored as `consent_root_v1` with timestamp; shown later in Device Info as "You accepted root tradeoffs on <date>".
3. **Persistent in-phone signal (AI inside the phone, not a chat tab)**: a slim amber chip pinned to the stream overlay's top-right reading `ROOTED`. Tap → sheet with live **Integrity Self-Check** (runs a bundled probe APK, shows BASIC/DEVICE/STRONG verdict + last run time) and a "Why did my bank app fail?" action.
4. **Failure interception, the key fix**: the in-phone agent watches for the signature failure modes (app crash <3s after launch, `SafetyNet`/`integrity` strings in logcat, known "device not supported" dialogs via OCR on the frame). On match it raises a **bottom sheet over the stream**: "Bank of X closed because this phone is rooted — not a Strlix outage." Buttons: **Clone to Verified Phone** (provisions a clean instance, copies nothing privileged, deep-links the same app), **Try Hide (Zygisk DenyList)** with an explicit "may stop working after app updates" line, **Dismiss for this app**.
5. **Hide is honest**: DenyList toggle per-app with a `last verified passing: <date>` field. Never claims permanent bypass.
6. **IA**: `Market → App detail` shows a **Root compatibility** row (Works / Degraded / Blocked) sourced from the same JSON, so the user sees it *before* install on a rooted phone.

## Android 7+ / graceful degradation notes
- Play Integrity API needs GMS ≥ 2021; on Android 7–8 images fall back to legacy **SafetyNet attestation**, and if neither is present show `Unknown — attestation unavailable` (never a fake green shield).
- OCR-based dialog detection is optional: if the OCR worker is absent, keep logcat + crash-timing detection only.
- Overlay chip is plain DOM over the video element — no WebGL, works on low-end browsers; if websocket events are unsupported, fall back to 30s polling.
- Zygisk DenyList absent on pre-Magisk-24 images → hide the toggle, show "Hiding unsupported on this image".
