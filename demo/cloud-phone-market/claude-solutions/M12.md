## Mistake restated
Competitors sell "real device" fingerprints on ARM/x86 emulator farms in datacenter IP space. Detection SDKs (Play Integrity, SafetyNet legacy, device-attestation libs, `ro.hardware=goldfish`, missing sensor jitter, ASN=cloud) flag them, users get bans, and the whole category loses trust. It persists because true device diversity (physical ARM SoCs, residential egress, per-device attestation keys) costs far more than a marketing checkbox.

## Strlix solution (concrete UX + IA)
**Principle: the fingerprint is a spec sheet, not a promise.** Every device SKU ships with a machine-generated, timestamped *Integrity Report* — sold as honesty, not as invisibility.

1. **Tier taxonomy visible at browse time** (three hard tiers, no marketing adjectives):
   - `Tier E — Emulated` (QEMU/x86, datacenter IP). Cheapest. Badge: grey chip "Emulator — detectable".
   - `Tier V — Virtualized ARM` (Redroid/KVM on ARM host, datacenter IP). Badge: amber.
   - `Tier D — Physical Device` (real SoC, per-unit attestation key, optional residential/mobile egress). Badge: green.
2. **Integrity Report drawer** (in-phone, swipe up from the device bezel — AI lives inside the phone shell, not a side chat). Rows with pass/fail/unknown + *last scanned* timestamp:
   `Play Integrity: MEETS_BASIC (not DEVICE)`, `ro.hardware`, `Build.FINGERPRINT origin`, `sensor entropy`, `GPU renderer string`, `IP ASN class`, `su/Magisk present`. Each row expands to "what apps can see this" plain-English.
3. **App Compatibility Matrix** per SKU: banking/wallet/social apps listed as `Works / Degraded / Known-blocks`, sourced from nightly automated probe runs, each with the probe date. Never "all apps supported".
4. **Pre-checkout attestation gate**: modal "This device will fail Play Integrity DEVICE. If your app requires it, choose Tier D." Requires explicit checkbox; recorded with order.
5. **In-phone AI agent** (`Strlix Assistant`, a system-level bubble inside the stream) answers "will WhatsApp ban me here?" by reading the live Integrity Report + matrix — it refuses to claim undetectability and offers a Tier D upgrade path.
6. **Live drift alerts**: if a running device's host is migrated or egress ASN changes, a persistent in-phone notification fires and the report re-scans.
7. **Honesty SLA**: if a delivered device's scan contradicts its listed tier, auto-credit; surfaced as "Integrity SLA" link on every SKU.

## Android 7+ / graceful degradation notes
- Probes must tolerate API 24: Play Integrity API unavailable → report `unknown (API<28)`, never silently `pass`.
- Client UI: no `:has()`, no container queries in the report drawer; flex fallback. `IntegrityReport` renders as a plain table if JS/WebGL absent.
- Stream: WebRTC → MJPEG → static screenshot + "reconnect" on old WebViews; report drawer stays functional in all three.
- Signed-JSON verification falls back to server-side verify when `crypto.subtle` is missing (http contexts on old Chrome).
