## Mistake restated
Competitors bill global users (IN/SEA) in a single USD ledger: prices shown in USD, no FX rate, no GST/VAT/SST line, no local rails (UPI/GrabPay/QRIS). Users see a card statement amount that differs from the checkout amount (issuer FX + cross-border fee), can't get a tax-compliant invoice, and dispute it. It persists because one currency = one ledger and no per-country tax/rail integration.

## Strlix solution (concrete UX + IA)
Everything renders **inside the phone frame** (the cloud Android surface), not a web checkout tab.

1. **Currency/tax resolution on session start.** `GET /v1/pricing/quote?sku=...&geo=IN` returns `{display_ccy:"INR", settle_ccy:"USD", fx:{rate:83.42, source:"ecb", captured_at, valid_until}, tax:{code:"IN-GST", label:"GST 18%", inclusive:true}, rails:["upi","card"]}`. Geo from billing address (not IP) with an explicit "Billing country: India ✎" chip — IP only pre-fills.
2. **Price tags everywhere are local-first.** Store cards show `₹499/mo` with a superscript ⓘ; tapping opens a bottom sheet: "₹499 incl. GST ₹76.12 · billed via USD at 1 USD = ₹83.42 (locked till 21 Sep, 23:59 IST)".
3. **Checkout receipt-before-pay panel** — a fixed 5-row ledger, never collapsed:
   - Plan (excl. tax) ₹422.88
   - GST 18% (HSN 998434) ₹76.12
   - Subtotal ₹499.00
   - FX: settled as $5.98 @ 83.42 (rate locked 15 min, countdown)
   - **"Your bank may add a cross-border fee"** warning row — hidden entirely when a local rail (UPI/Razorpay INR) is selected, replaced by "No FX — charged in INR by your bank".
4. **Rail picker ordered by locality**: UPI / Netbanking / Card (IN), GrabPay / PayNow / FPX / QRIS (SEA), Card (rest). Local rail = INR-settled, zero FX row → the main chargeback cause disappears.
5. **GSTIN / tax-ID field** for business buyers → invoice shows reverse-charge/`GSTIN` and place-of-supply; required for a compliant Indian invoice.
6. **AI inside the phone**: the on-device Strlix assistant overlay answers "why is this ₹499 not $5.99?" by reading the *same* quote object and narrating the line items — no separate chat product, no re-derived numbers.
7. **Wallet honesty.** Wallet balance stored in minor units of **settle currency** plus the display conversion: "Balance $12.40 ≈ ₹1,034 (rate today)". Top-ups record the locked rate per transaction; ledger is append-only `wallet_entries(amount_minor, ccy, fx_rate, tax_minor, rail, invoice_id)`.
8. **Post-purchase**: Settings → Billing → Invoices, per-invoice PDF/HTML with tax breakup and FX audit line; "Dispute this charge" button opens an in-phone form *before* the user calls their bank (pre-chargeback deflection).

## Android 7+ / graceful degradation notes
- Bottom sheet and ledger are plain DOM + CSS (no `backdrop-filter`, no container queries); WebView 51-safe ES2017 build target.
- `Intl.NumberFormat` currency-display may be missing/partial on Android 7 WebView → ship a tiny symbol+grouping formatter fallback; never render a bare number.
- No `Intl.RelativeTimeFormat` for the rate countdown — use `mm:ss` string.
- If the `:8789` stream drops, checkout falls back to plain HTTP POST of the last-known quote; if the quote is stale, block pay with "Refresh price" rather than charging an old rate.
- UPI intent deep-links (`upi://pay`) tested on Android 7; if no handler, fall back to QR image + card.

## Acceptance criteria
- For `geo=IN|SG|MY|ID`, every store price and the checkout ledger render local currency, an explicit tax line with rate+label, and either an FX row (rate, settle amount, lock expiry) or a "charged in local currency, no FX" row — asserted in `checkout-ledger.spec.ts`.
- Selecting a local rail removes the FX row and cross-border warning; selecting card restores them, with no page reload.
- Sum check: `plan + tax == subtotal` and `subtotal / fx_rate == settle_amount` within 1 minor unit, on integer math, for all fixtures.
- Expired rate lock (>15 min) disables the pay button and offers "Refresh price"; no charge can be submitted with a stale `fx.captured_at`.
- Every completed test-mode purchase yields a retrievable invoice with tax breakup, optional GSTIN, place of supply, and the FX audit line; loads on Android 7 WebView with correct currency formatting.
