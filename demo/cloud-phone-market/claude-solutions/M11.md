## Mistake restated
Competitors ship cloud phones on obvious datacenter ASNs, sell proxy as a post-purchase upsell, and never verify the result — so WebRTC, DNS, and IPv6 still leak the host IP. The user only discovers this after an account ban. Root cause: gaming-grade SKUs resold into SMM/multi-account use, plus margin on proxy add-ons.

## Strlix solution (concrete UX + IA)
**Network identity is a required step of phone creation, not an add-on.** No phone can reach ONLINE state without a bound egress.

1. **Create Phone → Step 2 "Network identity"** (cannot skip). Three tiles: *Bring your own proxy* (HTTP/SOCKS5/WireGuard paste or `user:pass@host:port`), *Strlix mobile IP* (residential/mobile pool, region picker), *Datacenter (testing only)* — the last tile is visually marked red and locks the phone to a `TESTING` badge that persists in the phone list and cannot be removed without re-binding.
2. **Leak Test before first boot.** In-phone full-screen check (runs inside the Android container, not the browser) with 5 rows: Egress IP + ASN type, DNS resolver ASN, WebRTC STUN candidates, IPv6, Timezone/locale vs IP geo. Each row PASS/FAIL with the actual observed value. Boot button stays disabled until 0 FAIL or user types "I accept ban risk".
3. **Auto-remediation, not a report.** Each FAIL has one fix button applied at the container level: WebRTC → block STUN/TURN ports via iptables in the phone's netns; DNS → force resolver through proxy tunnel; IPv6 → disable in netns; Timezone → set Android TZ/locale/`persist.sys.timezone` to match IP geo. AI-in-phone surfaces this as an overlay card: "Your WebRTC is leaking 103.x.x.x. Fix it? [Fix & reboot]".
4. **Persistent IP chip in the phone toolbar**: `🟢 IN · Jio · mobile` — tap for the leak panel. Turns amber on ASN change, red on leak detected mid-session and pauses automation.
5. **Daily background re-test** per phone; history strip (30 days) so an IP rotation that silently broke things is visible. Export leak report JSON for the user's own audit.
6. **Bundled pricing**: mobile egress included in the SMM plan's phone price. Proxy is never a checkout upsell line item.

## Android 7+ / graceful degradation notes
- Enforcement lives in the host netns/iptables, so Android 7 containers need no VPNService and no root app.
- If VpnService-based per-app routing is unavailable (API < 24 edge), fall back to netns-only routing; UI shows "system-level" instead of "per-app" and hides the per-app split toggle.
- WebRTC block is port/IP-level, so it holds on old WebViews.
- Leak panel degrades to plain table without sparkline history on low-end browsers; `IpChip` renders text-only if emoji/flag fonts are missing.

## Payment notes

## Acceptance criteria
- A phone cannot reach ONLINE without a bound egress; datacenter choice forces a persistent `TESTING` badge.
- Leak test runs inside the container and reports real values for IP/ASN, DNS, WebRTC, IPv6, timezone; boot blocked on FAIL unless explicitly overridden.
- Each FAIL has a working one-tap fix that changes the re-test result to PASS.
- Mid-session ASN change or leak flips the toolbar chip red, pauses automation, and pushes a `net.leak` event over the existing :8789 stream.
- No proxy line item appears in checkout; plan includes egress.
