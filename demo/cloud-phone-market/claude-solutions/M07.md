## Mistake restated
VSPhone-class hosts force-reboot busy instances to reclaim oversubscribed capacity. The reboot restores a base image, so apps installed during the session (and their game saves/logins) vanish. Users lose AFK farming progress and trust; vendors keep doing it because live migration costs more than a reset.

## Strlix solution (concrete UX + IA)
Principle: **the phone's disk outlives the phone's host.** Session state is never the source of truth.

1. **Persistent /data overlay (Vault).** Every instance boots base image + user CoW overlay stored on network volume. Reboot/migration re-attaches the overlay; installed APKs, saves, logins survive by default. Marketing string in UI: "Your apps survive reboots."
2. **In-phone AI agent, not a chat sidebar.** A floating "Strlix Orb" lives *inside* the Android surface (system overlay app). On any reclaim/health event it: pauses the foreground game via its own accessibility hook, writes a snapshot, then shows an in-phone card: "Host maintenance in 60s. I'm saving your game and moving you." Countdown ring + "Move now" / "Give me 5 min" (one deferral, max 15 min, shown as a budget).
3. **Snapshot-before-anything rule.** No control-plane action (reboot, migrate, evict, resize, plan change) is allowed unless a snapshot completed in the last 90s. Failure to snapshot = action blocked, capacity taken from an idle instance instead.
4. **Restore Point tray.** In-phone drawer: last 5 auto-snapshots (labelled "before reboot 14:02"), plus manual "Pin this moment." One-tap rollback, diff shown as app-list delta ("+ Genshin 12.4 GB, + 3 saves").
5. **AFK Guard mode.** Toggle in phone quick settings. While on: instance marked non-evictable tier; if hardware genuinely dies, we resume on a new host from the ≤60s snapshot and the Orb posts a timeline card "Resumed at 03:11, lost 38s of play."
6. **Incident receipt + credit.** Any uncontrolled restart auto-issues a receipt card with lost-seconds measured, and auto-credits runtime minutes — no support ticket.
7. **IA:** `Phone` (default full-bleed stream) → Orb → {Restore Points, AFK Guard, Health & Incidents, Storage}. Market/billing lives *behind* the phone, not above it.

## Android 7+ / graceful degradation notes
- Orb overlay uses `TYPE_APPLICATION_OVERLAY` on 8+, `TYPE_PHONE` fallback on 7.x; if overlay permission denied, degrade to a top-edge banner rendered by the web client over the stream (works everywhere, no perms).
- No WebRTC/H.264 on old WebViews → fall back to MJPEG-over-WS at 15fps; lifecycle cards are DOM, so warnings render even when video is degraded.
- Offline/backgrounded client: snapshot still taken server-side; user sees the incident receipt on next open.
- Low storage: overlay quota bar in Storage; warn at 85%, never silently reset.

## Acceptance criteria
- Installing an app mid-session, then triggering a forced reboot, leaves the app and its save data present after resume.
- `POST /api/drain` returns 409 when the newest snapshot is older than 90s; no instance is ever reclaimed without a fresh snapshot.
- Planned reclaim shows the in-phone Orb card ≥60s ahead, with a working single deferral and a visible countdown.
- Unplanned restart produces an incident receipt with measured lost-seconds and an auto-applied test-mode credit, with zero user action.
- On Android 7 with overlay permission denied and no WebRTC, the user still sees the warning banner and can open the Restore Point tray.
