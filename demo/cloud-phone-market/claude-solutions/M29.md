## Strlix solution (concrete UX + IA)
**The Hero Mini-Phone.** Homepage above the fold = one centered 280×600 phone shell (real device bezel, rounded 36px, subtle shadow), already **live and warm**, not a screenshot.

1. **Idle state (0s, no click):** the mini-phone plays a ~6s muted looping WebM of the Strlix launcher — AI assistant bubble pulsing, an app opening. Poster frame renders instantly; video swaps in on `canplay`. Single CTA pill under it: **"Tap to take control →"**.
2. **Tap → Claim (≤1.5s):** `POST /api/trial/claim` from web-market hits desktop-api `:8789`, which allocates a pooled pre-booted device (never cold-boot on click) and returns `{sessionId, wsUrl, ttl:300}`. The mini-phone shows a 3-dot "waking your phone" shimmer *inside the bezel* — never a page-level spinner.
3. **Live mini-phone (still small):** WS stream replaces the loop in the same DOM node, same bezel, same position — zero layout shift. Touch/click is now forwarded. A 5:00 ring counts down on the bezel corner. User is *using Android* without a signup, a plan, or a region picker.
4. **Fullscreen expand:** a corner ⤢ button (and double-tap) runs a FLIP transform — bezel scales from hero rect to viewport rect in 320ms, `requestFullscreen()` on the container, stream re-negotiates to a higher bitrate/res tier. No navigation, no route change, no reconnect. Escape/swipe-down reverses the same FLIP.
5. **AI is inside the phone.** No side chat panel. In fullscreen, a floating Strlix orb sits in the Android overlay layer; tapping it opens an in-device sheet that drives real taps ("install WhatsApp", "set this up as my second number").
6. **Conversion moment:** at T−60s an in-phone system-style notification slides down: "Keep this phone — 3 plans". Tapping opens the paywall *inside* the device frame. Tables/specs live at `/compare`, reachable only from a text link below the fold — they exist, they just aren't the front door.

## Android 7+ / graceful degradation notes
- Android 7 Chrome/WebView lacks reliable WebRTC insertable streams → ladder: **WebRTC → MSE H.264 baseline → MJPEG-over-HTTP** at 15fps, chosen by `lib/stream/fallback.ts` capability probe, not UA sniffing.
- `requestFullscreen` missing on old WebView → fall back to a fixed-position `position:fixed;inset:0` pseudo-fullscreen + `visualViewport` sizing.
- No `View Transitions` API → FLIP via plain `transform`/`will-change`; `prefers-reduced-motion` skips the animation and cross-fades.
- Autoplay blocked → poster stays, CTA copy switches to "Tap to start".
- `<2GB` RAM or `saveData` → skip the hero loop entirely, ship the WebP poster.
