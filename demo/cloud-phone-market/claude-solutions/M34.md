## Mistake restated
Dark "device farm" grids use tinted status chips (e.g. `#2E7D32` green on `#121212`) whose text/background contrast falls below WCAG 4.5:1, and which encode state by **hue alone**. In a 200-device table at a glance, "online" and "offline" look identical, so the operator opens the wrong phone — an expensive error when the wrong session is mutated.

## Strlix solution (concrete UX + IA)
1. **Triple-encoded status**, never hue-only. Each device tile/row shows: (a) glyph — ● online, ◐ booting, ○ offline, ▲ error; (b) uppercase text label `ONLINE`; (c) color. Glyph+label survive greyscale and deuteranopia.
2. **Contrast-locked token set.** Status colors live in `tokens/status.json` only, with foreground/background pairs pre-verified ≥ 4.5:1 on the two surface tokens (`--surface-0 #0E1116`, `--surface-1 #171B22`). Chips are *filled with an opaque* token (not `rgba(green,.15)`) so contrast is deterministic and not compositing-dependent.
3. **Left edge rail, not a chip.** Each row gets a 4px status rail plus a 3-state pattern (solid / dashed / hollow). Scanning a column of rails beats scanning inline chips.
4. **Confirm-by-identity on open.** Clicking a device opens a stream sheet whose header repeats device name, last 4 of serial, and status; an offline device shows a full-width `OFFLINE — cannot stream` bar instead of a black canvas (the current silent black frame is what makes people think they opened the right phone).
5. **AI inside the phone.** The assistant is a floating pill *over the device stream canvas*, not a side chat. Asking "which of these are offline?" makes it dim non-matching tiles in the grid and pin a count chip — it manipulates the grid, it doesn't describe it.
6. **A11y switch in header**: `High contrast` toggle bumps to a 7:1 (AAA) palette and thickens rails to 6px; persisted in localStorage.
7. **CI gate**: a contrast unit test iterates every token pair and fails the build under 4.5:1 — that is what stops the regression from persisting.

## Android 7+ / graceful degradation notes
- Chromium 60-era WebView: avoid `color-mix()`, `oklch()`, `:has()`. Ship literal hex from `status.json` at build time; CSS vars are fine (Android 5+).
- No `backdrop-filter` — the blurred chip is the main contrast offender anyway; use opaque fills.
- If WebGL/MSE is unavailable, StreamSheet falls back to 2 fps JPEG polling from :8789 and labels itself `LOW-FPS MODE` rather than failing silently.
- `prefers-contrast` unsupported on 7; the manual High-contrast toggle is the fallback path.

## Acceptance criteria
- Every status token pair measures ≥ 4.5:1 against both surfaces; `test/contrast.spec.ts` fails the build otherwise.
- Grid remains fully readable in forced greyscale and under deuteranopia simulation (glyph + label carry state).
- Opening an offline device shows an explicit OFFLINE banner with device name and serial suffix — never a black canvas.
- High-contrast toggle reaches 7:1 and persists across reloads.
- Renders and streams on Android 7 WebView with no `color-mix`/`backdrop-filter` in the shipped CSS.
